# 挑水果

用手機鏡頭對準水果或蔬菜，即時辨識是哪一種，並顯示挑選技巧。辨識全部在手機瀏覽器內完成（MobileCLIP-S0 + Transformers.js），不需要付費 API，也不會上傳照片。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html`、`style.css`、`app.js` | 網頁本體 |
| `fruits.js` | 43 種水果、46 種蔬菜的挑選技巧與給 CLIP 比對的英文描述 |
| `embeddings.json` | 每種蔬果的分類向量（文字特徵再用真實照片微調，由 `tools/train.mjs` 產生） |
| `refs.bin` | 內建參考樣本：約 1,700 張真實照片的影像特徵（int8，約 0.9MB） |
| `tools/` | 產生上述檔案的腳本（見下方「新增或修改蔬果」） |

## 本機預覽

```bash
python tools/serve.py
```

電腦開 http://localhost:5500 即可（這個伺服器關閉了快取，改完程式重新整理就會生效）。手機要開相機，網址必須是 **https**，所以要部署到 GitHub Pages、Cloudflare Pages、Vercel 或 Netlify 這類免費的靜態網站服務（把整個資料夾上傳即可，不需要 `tools/`）。

## 新增或修改蔬果

1. 編輯 `fruits.js`（水果放 `FRUITS`、蔬菜放 `VEGETABLES`；`names` 用英文描述外觀，越具體越好；`cue` 是二選一時顯示的外觀重點）
2. 在 `tools/` 依序執行：

   ```bash
   npm install
   node build-embeddings.mjs   # 文字特徵 → tools/text-embeddings.json
   node collect-photos.mjs     # 從維基共享資源下載照片到 tools/photos/（不進 git）
   node embed-photos.mjs       # 計算照片的影像特徵
   node train.mjs --write      # 比較各種做法，測試集有變好才寫入 embeddings.json 與 refs.bin
   ```

## 備註

- 這個模型的 q8／uint8 量化版本辨識結果是錯的，所以影像模型改用 fp16（約 23MB，第一次開啟時下載，之後由瀏覽器快取）。
- 認錯時，點候選或用「手動選蔬果」選正確答案，App 會把當下畫面記在這支手機的 localStorage，之後遇到類似畫面會更準。
- 準確度（維基共享資源約 3,200 張照片，依檔名固定分成訓練 50%／驗證 20%／測試 30%，以下是 715 張測試照片）：只用文字 59.6% → 文字微調＋參考樣本 **74.4%**；正確答案在前兩名 75.4% → **85.0%**。
- 前兩名分數接近（差距 < 0.3）時改成讓使用者二選一：在測試集上約 16% 的照片會詢問，「直接給錯答案」從 25.6% 降到 14.3%。
- 測試照片和訓練照片同樣來自維基共享資源，實際用手機鏡頭拍的提升幅度可能會小一些。
- 比較容易混淆的組合：蓮霧、蜜棗、柑橘類；苦瓜和絲瓜；地瓜和馬鈴薯；芋頭和山藥；大番茄和小番茄；覆盆莓和草莓；洋菇和杏鮑菇；帶葉的紅蘿蔔和芹菜。香蕉、芒果、鳳梨、青花菜、茄子、洋蔥這類很穩定。
- 刻意沒有加入：葉菜類（菠菜、空心菜等，外觀太相近）、美濃瓜與金桔（測試照片全部認錯，金桔一律被認成柑橘）。
- 手機瀏覽器可能因記憶體不足或切到背景而關掉網頁。App 會自動重新開啟相機；若判斷是異常關閉，會改用較省資源的 CPU 模式。辨識結果穩定後也會自動降低辨識頻率，減少發熱。
